# T-batch — issue #100 capture arm — MANIFEST

Worker: `opus5:lexec`. **Capture only.** Nothing in this section states which outcome is
correct, and no arm is classified. The observation per arm is: the nudge counts, the three
separated streams, and the watchdog's own per-cycle verdict lines. Seats classify.

## Objective as executed

What a declared quiet state does when the pane changes, **separated by who caused the
change**. Six arms: three change-sources × two quiet states.

| source | construction |
|---|---|
| **A** NUDGE-ONLY | the state is declared and NOTHING further is written to the observed pane |
| **B** INDUCED RESPONSE | the state is declared; after a bounded wait for a nudge event, ONE fixed canned line is written to the observed pane, and the state is NOT redeclared |
| **C** UNOWNED CHANGE (control) | the state is declared and the observed pane is changed by a human-like typed write, with no agent involvement and with zero nudges having fired first |

Quiet states: `waiting-user`, `blocked`.

## The observation tables

**`TABLES.txt` is generated by `_harness/t100-mktables.sh` from the arm artifacts.** Every
value in it is read out of an `ARM.txt`, `ledger.tsv`, `hash-timeline.txt` or
`watchdog-verdict-lines.txt`; nothing in it is typed by hand. Regenerate it at any time
and it must reproduce. It carries four tables: nudge counts per arm, the instrument live
control plus the declaration, the frozen scrubbed hash at each named observation point,
and the watchdog's own per-cycle verdict classes with occurrence counts.

## The three streams, kept separate

| stream | per arm |
|---|---|
| 1. RAW pane bytes | `pane.<label>.raw` at every observation point, each with a byte-for-byte `pane.<label>.od` (`od -c`). Captured with the watchdog's OWN range, `capture-pane -p -J -S -40 -E -`, so the bytes are the ones the product reads |
| 2. SCRUBBED hash | `hash.<label>.txt` at every point, plus `hash-timeline.txt`. Computed by calling **the frozen `_watchdog_quiet_hash` itself** — see below |
| 3. event timeline | `events.<label>.jsonl` at every point, plus `event-timeline.txt` (every `nudge` and `state` row in order, with timestamps) and `watchdog-verdict-lines.txt` (the watchdog's own log for the observed agent, read from its `_watchdog` pane) |

### The scrubber is the frozen one, never a reimplementation

`scrubber-provenance.txt` per arm records it: `_watchdog_quiet_hash` and
`_watchdog_capture_pane` are extracted by `awk` range **from that session's own generated
`watchdog` script** — the artifact that actually runs — and the session's own generated
`_lib` is **sourced**, exactly as the watchdog prologue sources it, so `_ae_md5` is the
real one. The file records the source paths, their sha256, and the extract's sha256.
Extraction runs under `LC_ALL=C` **for the extraction only**, because the generated `_lib`
carries a raw byte-class regex that is not valid UTF-8 and `awk` aborts on it under a
UTF-8 locale; the arms' runtime locale stays the pinned UTF-8 everywhere else.

## The per-arm ledger, written BY the checks as they run

`ledger.tsv` per arm: one timestamped row per check, appended by the check itself at the
moment it runs — never assembled afterwards. It carries the knobs, the launch rc, the
agent pane and ref, the scrubber extract hash, both halves of the instrument control, the
forced-yield settle, the declaration and its rc, the relocated echo, the arm's own write,
and, at every observation point, the raw byte count, the raw sha256, the scrubbed hash,
the events line and nudge counts, and the watchdog log line count.

## Instrument live control — run per arm, BEFORE any measurement

`ARM-INVALID` unless BOTH halves hold, because a later unchanged hash could not otherwise
be sourced to the product rather than to the recorder:

1. **a plain pane write must be REGISTERED** — the controller writes a marker to the
   observed pane and the frozen scrubbed hash must change;
2. **a nudge-shaped block must NOT be registered** — the same buffer with an envelope +
   nudge block appended must hash the same, which is the discriminator the product itself
   uses.

Both are recorded in `ledger.tsv` and reported in TABLE 2. A subtlety that had to be
fixed before the control was sound, and is stated because it would silently bias the
result: the frozen scrubber receives its buffer through a command substitution, which
strips trailing newlines, so a pane's empty bottom rows survive when text follows them and
vanish when it does not. The nudge-block control is therefore built on the **stripped**
base (`pane.ctlbase.raw`), so both sides are compared on the same footing.

## Fixture construction, stated in full

- **Unmodelled tool, deliberately.** The agent is a renamed copy of `bash` named `grok`,
  running `t100-fake.sh`, which renders every complete line it reads **verbatim** — what
  an unmodelled pane does with delivered text, not an invented TUI rendering. `grok` is
  chosen because ae's send path gates delivery on a readiness sensor for the TUI-modelled
  tools; against a fake that does not present their idle screen every nudge is
  undeliverable, which would have made these arms about delivery instead of quiet states.
  Measured during fixture construction and recorded here: with a `claude`-named fake the
  watchdog reached the stale branch and logged `nudge NOT delivered (rc=1)`; with the
  unmodelled tool the nudges are delivered and appear as `nudge` events.
- **Forced initial yield, then settle, before the declaration.** A marker is written to
  the observed pane so it demonstrably CHANGES, then the scrubbed hash is polled until two
  consecutive samples match. `ARM-INVALID` if it never settles within the bound, because
  no stable baseline would have existed when the state was declared. Both the sample count
  and the settled hash are in `ledger.tsv`.
- **The declaration runs through the REAL `state` helper.** It resolves the declaring
  agent from the current pane, so a pane carrying the agent's `@ae_agent`/`@ae_slot` is
  planted in a SEPARATE window for the call (`planted-pane.txt` records what it did and
  what it did not change). **The planted window is killed immediately afterwards**: while
  it exists the watchdog sees a second pane for that agent whose process is a plain shell
  and classifies the agent dead, and a dead-classified agent is skipped before the
  question this arm is about is ever reached. Every arm asserts, at the end, that no
  `DEAD` line appears in the watchdog's own log, and writes `ARM-INVALID` if one does.
- **The declaration echo is relocated to the observed pane.** In a real session the
  `state` helper runs in the agent's own pane and its echo lands there — which is exactly
  the line the frozen scrubber exists to remove. The helper's **own stdout bytes** are
  written verbatim to the observed pane's tty; nothing is reshaped. Recorded per arm in
  `ledger.tsv` (`declare echo.relocated`) and in `writes.txt`.
- **Writes reach the observed pane as pane OUTPUT**, straight to its tty, and every write
  is recorded in `writes.txt` with its label, target tty and exact text.

### Arm C's attribution requirement

Arm C means something only if its write is one the product would attribute to a human
rather than to the watchdog. That is asserted twice, per arm, and both are in the
artifacts: the instrument control shows the recorder REGISTERS a plain pane write and does
NOT register a nudge-shaped block (TABLE 2), and the arm asserts that **zero nudges had
fired before the write** — `ARM-INVALID` if the nudge count moved first, rather than a
difference that could not be sourced. `ledger.tsv` carries `source nudges.before.write`.

### What B records when no nudge arrives first

B waits a bounded 45 s for a `nudge` event before writing its canned line. Whether one
arrived is recorded per arm as `nudge_observed_before_write` and appears in TABLE 2; the
line is written at the bound either way, and the ledger says which happened
(`source nudge.observed` or `source nudge.not.observed`). The bound is not converted into
an absence.

## Known limits of this section, stated

- The observed pane's rendering is the unmodelled shape. A TUI-modelled tool renders a
  delivered nudge differently (a submit ornament plus an indented block), and the frozen
  scrubber handles that shape by a different branch. This section exercises the raw
  branch only; the rendered branch would need a harvested real idle screen and is not run
  here.
- The watchdog's per-cycle lines are read from its `_watchdog` pane, so they are subject
  to that pane's scrollback bound; `wdlog.<label>.txt` is captured with `-S -400`.
- Four instrument defects were found and fixed BEFORE any arm was accepted, each because
  a check was run against the instrument rather than trusted: the planted pane polluting
  the roster (fixed by retiring it and by the DEAD assertion), the declaration echo
  landing in the wrong pane (fixed by relocating the helper's own bytes), `grep -c`
  emitting its count twice on a zero result and corrupting every later arithmetic (fixed
  at both sites), and nudge delivery being gated by the send path's readiness sensor
  (fixed by using an unmodelled tool). The first accepted run of every arm is the one in
  this tree.
