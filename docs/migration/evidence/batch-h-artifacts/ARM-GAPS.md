## The pattern behind three of these

An upstream guard foreclosed the fact under test, and every time the cases reported
IDENTICALLY — which reads as "no difference here" and is actually "the question was never
asked": a cwd fallback behind a token path that selects first, a refresh-restart branch
behind a liveness gate, and selector spellings behind a config-presence check.

Preventive rule, applied from A-H8 onward: **before building a case, enumerate the guards
that precede the fact under test and confirm the fixture passes them.** One read of the
call path. A fixture author reasons forward from the manipulation to the expected
observation and does not naturally enumerate what sits between them.

Disposition when it happens anyway: keep the cases for what they DO establish and build a
separate pair for the original question. Rebuilding in place throws away a true observation
to test a different one.
